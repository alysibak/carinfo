# CarInfo

A full-stack car comparison and discovery platform. Browse, search, compare, and analyze **15,470 synthetic vehicles** across 31 makes (1995–2025). No database server and no authentication — the backend loads a static JSON file into memory, and user garages persist in the browser.

## Tech Stack

| Layer | Stack |
|---|---|
| Frontend | React 18, TypeScript, Vite, Tailwind CSS, Zustand, React Router v6, Recharts |
| Backend | Express, TypeScript, in-memory indexed search |
| Production API | Vercel serverless functions (`api/`) sharing the same service layer |
| Data | `server/data/cars.json` (~17 MB, generated offline) |

## Quick Start

```bash
npm install
npm run dev        # client :3000, server :5000 (Vite proxies /api)
npm run build      # builds client + server
npm run start      # production Express server (requires build first)
```

**Requirements:** Node.js 18+

## API (7 endpoints)

All responses: `{ success: true, data: ... }` or `{ success: false, error: "..." }`.

| Method | Path | Description |
|---|---|---|
| GET | `/api/health` | Health check |
| GET | `/api/cars/makes` | All unique makes |
| GET | `/api/cars/makes/:make/models` | Models for a make |
| POST | `/api/cars/search` | Filtered search with pagination |
| GET | `/api/cars/:id` | Single vehicle by ID |
| POST | `/api/cars/compare` | Batch lookup by IDs (max 5) |
| GET | `/api/cars/stats/overview` | Database statistics |

**Deployment modes:** Express locally (`server/`), Vercel serverless in production (`api/`). Both import `server/src/services/car.service.ts`.

## Data

The vehicle database is **synthetic**, generated by `server/scripts/generate-massive-database.ts`. NHTSA integration exists only in offline scripts (`fetch-nhtsa-real-data.ts`, `generate-portfolio-database.ts`) — not at runtime.

### Schema normalization

The on-disk JSON uses field names that differ from the TypeScript types:

| On disk (`cars.json`) | Normalized (API wire format) |
|---|---|
| `country` | `countryOfOrigin` |
| `drivetrain` | `driveType` |
| `pricing.msrp` / `minPrice` / `maxPrice` | `price.msrp` / `min` / `max` |
| `engine.displacement` (`"2.4L"`) | `engine.displacement` (number) |

`car.service.ts` normalizes every record once at module load, before building indexes. Do not change the on-disk JSON — add mappings in the normalization layer if the schema evolves.
